# MUSIC ROOM architecture (repository: music-room)

Static GitHub Pages application. No backend, accounts, microphone, uploads or CDN. Editable composition data and rendering remain in the browser. Same-origin piano and CC0 orchestra samples are fetched only following an explicit audio action, for the notes actually used. WEB LAB's shared storage is never read or written.

Layers: `model.js` owns validated musical data, history and MIDI/MusicXML encoding; `timeline.js` owns pure tempo/meter maps, bars and tick/second conversion; `midi-import.js` owns bounded binary SMF parsing and selection validation, never DOM or storage; `instruments.js` owns instrument identity, GM mapping and ranges; `sampler.js` owns bounded same-origin asset loading; `editing.js` and `templates.js` own pure composition operations; `audio.js` owns native Web Audio voices, scheduling and WAV rendering; `notation.js` owns VexFlow engraving and PDF; `app.js` owns DOM interaction. Libraries are pinned and bundled into same-origin vendor modules. Build tooling is not required by visitors.

Performance data uses 960 ticks per quarter note. Printed notation explicitly quantizes to a sixteenth-note grid. Quantization never modifies the composition, MIDI or audio. MusicXML retains original tick durations, with separate voices for overlapping notes. Piano sample fidelity is that of the redistributed MP3 files, not the original multi-velocity raw bank.

Limits: 16 tracks (up to 15 melodic tracks and one percussion-kit track; MIDI channel 10 is reserved), 4096 notes, sounding MIDI pitches 21–108. Version-1 projects retain 64 bars, integer 40–240 BPM and 4/4, 3/4 or 6/8. User-approved D09 introduces version 2 for MIDI imports: up to 512 bars, exact 24-bit MIDI microseconds-per-quarter and tick-indexed tempo/meter maps (2048 each), meter numerator 1–32 / denominator 1,2,4,8,16,32. A mid-bar change closes a partial bar without moving notes. No silent truncation or transposition. Legacy files and unknown legacy metadata remain readable. Pitched percussion, including timpani, uses a melodic channel. Sample cache is bounded to 128 MiB decoded PCM and four concurrent downloads. Real-time voices are bounded to 96; older voices may be released at that boundary, while offline rendering includes all notes. Offline WAV exports remain limited to 180 seconds including release tails. SVG/PDF/onscreen engraving is limited to 128 pages and requires bar boundaries on its labelled 1/16 grid; unsupported engraving leaves MIDI, audio and exact MusicXML intact. One bounded composition is saved under `score-lab-project-v1`; malformed existing data is preserved until explicit replacement.

MIDI import: local-only SMF 0/1 with PPQ division, at most 2,000,000 bytes, 256 source tracks, 512 chunks, 200,000 parsed events, 100,000 candidate notes, 20,000 retained channel events and a 1e9 source/converted tick bound. The UI shows source-track/channel parts and a selection preview; conductor tempo/meter data does not consume a musical track. A validated selection must satisfy the 16/15+1 and 4096 limits before explicit replacement. Cancel, malformed files and stale asynchronous reads preserve the current song. SMPTE and format 2 fail explicitly. Timing converts to 960 PPQ with disclosed rounding. GM program changes affect note-on sound choice; missing instruments use disclosed local approximations, retaining original MIDI program numbers until explicit instrument replacement. CC/pedal and pitch bend are preserved for MIDI re-export but are not applied to playback. Unknown metadata, lyrics/markers/key signatures, SysEx and pressure are omitted with warning. No binary file is uploaded or retained secretly.

Repository and Pages path become `music-room` under explicit user request. Keep the original localStorage key: GitHub Pages paths share the same origin, so this is not a data migration or an isolation boundary. Update the gallery/source links. GitHub repository redirects do not promise an old Pages URL redirect; do not create a second old-name repository or alter the personal root site.

Safety envelope for imported timing: 4–1000 quarter-note BPM (exact 60,000–15,000,000 microseconds), reject rather than clamp. Repeating an audio range shorter than 50ms is refused. A scheduling window creates at most the most recent 96 candidate voices, instead of allocating thousands and immediately discarding them. WAV still renders the complete composition. These bounds apply independently of binary file validity.

VSCO Community Edition samples are redistributed under CC0 with pinned source/mapping revisions and per-file hashes. The compact bank uses one dynamic layer, mono PCM16 at the original 44.1/48 kHz rate, bounded durations and crossfaded sustain loops. Velocity controls amplitude, not true multi-layer timbre. This is a browser composer, not a VST host or a full orchestral sample library. Audio downloads have no third-party origin. Session-only selection, edit tool and loop settings do not add storage keys.

See docs/decisions.md. Changes to these boundaries require a documented decision.
